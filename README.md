# Cabbage Market

당근마켓을 모티브로 만든 중고거래 사이트입니다. 게시글의 판매자와 구매자가 채팅으로 거래 조건을 조율할 수 있도록 구현했습니다.

## 프로젝트 정보

- 기간: 2023.11.14 ~ 2023.11.30
- 인원: ITWILL 학원생 6명
- 담당: 채팅 기능, 팀원 코드 통합

## 기술 스택

- Backend: Java 8, Spring (Legacy), JSP / JSTL, Oracle, MyBatis
- Frontend: HTML, CSS, JavaScript, jQuery, AJAX

## 채팅 기능

- 게시글별 판매자·구매자 채팅방 생성
- 메시지, 사진, 이모티콘 전송
- 전송 후 5분 이내의 본인 메시지 삭제
- 판매자의 최종 가격 결제 요청과 구매자의 링크 결제 흐름
- 채팅방을 나가면 해당 사용자 계정에서만 대화 내용 제거

## SSE 기반 실시간 메시지 전달

**문제** — 채팅 메시지는 서버에 저장되어야 하고, 저장 후에는 상대방 화면과 읽음 상태를 갱신해야 했습니다.

**선택** — 클라이언트에서 서버로 메시지를 보낼 때는 HTTP/AJAX 요청을 사용하고, 서버에서 클라이언트로 채팅 이벤트를 전달할 때는 SSE를 사용했습니다. `SseEmitter`를 사용자 ID와 생성 시간으로 관리하고, timeout·completion·전송 실패 시 emitter를 제거합니다.

**이유** — 현재 구현에서 실시간성이 필요한 지점은 서버가 발생시킨 이벤트를 클라이언트에 전달하는 방향입니다. 메시지 저장 요청은 기존 요청/응답 방식으로 처리할 수 있으므로, 완전한 양방향 지속 연결 대신 서버 이벤트 스트림과 HTTP 요청을 함께 사용했습니다.

### 재연결 시 최근 이벤트 복구

SSE 연결은 다시 열 수 있어도, 연결이 끊긴 사이의 이벤트는 누락될 수 있습니다. 이를 줄이기 위해 이벤트 ID를 부여하고 최근 이벤트를 5분 TTL의 캐시에 보관했습니다. `Last-Event-ID`가 전달된 재연결에서는 마지막 이벤트 이후 캐시에 남아 있는 항목을 정렬해 재전송합니다. 메시지·읽음 상태는 이벤트 이름으로 구분해 구독 중인 사용자 emitter에 전달합니다.

캐시는 최대 10,000건을 메모리에 보관합니다. 이 방식은 구현을 단순하게 만드는 대신, 서버가 재시작되었거나 TTL이 지난 이벤트까지 보장하는 영속 메시지 큐는 아닙니다.

**결과** — 메시지 저장과 서버 알림을 각 통신 방향에 맞게 분리했고, 짧은 연결 단절에서는 최근 이벤트를 다시 전달할 수 있게 했습니다.

## 파일 업로드 직후 사진이 보이지 않던 문제

**문제** — 프로젝트 내부 리소스 디렉터리에 업로드한 사진이 인식되기까지 약 8초가 걸렸습니다.

**선택과 결과** — 사용자 업로드 파일을 프로젝트 외부 경로로 분리하고 `server.xml`의 Context 설정으로 `/resource/pic` 요청을 해당 경로에서 찾게 해, 업로드한 사진이 즉시 반영되도록 개선했습니다. 배포 리소스와 런타임 생성 파일을 분리한 대신, 외부 저장 경로와 서버 매핑을 함께 관리해야 합니다.
